

# v1.1.0 Resume Anchor

本ファイルは、PHR identity v1.1.0 の再開用アンカーである。
以後このフェーズを再開する際は、本ファイルの内容を前提として扱う。
推論で過去経緯を補わず、まず本ファイル → ADR-0015 → ADR-0016 → 関連specの順で確認する。

---

## 1. 位置づけ

- v1.0.3 では、既存構造を大きく壊さずに各系統へ `person_id_custom` / `identity_hash` を通すところまでを完了した
- イベントを正式テーブルで持つ設計や、identity ロジックの共通ライブラリ化は v1.1.0 へ送られた
- v1.1.0 は、**identity 生成と正規化の共通化を再設計するフェーズ**である

---

## 2. このフェーズで固定した原則

### 2.1 三層構造

identity の扱いは以下で固定する。

```text
raw → match(canonical) → hash
```

### 2.2 責務分離

- `primitive` / `base_norm`
  - 文字・構造の正規化
- `field`
  - 項目ごとの canonical 生成
- `builder`
  - ID生成のみ

### 2.3 禁止事項

- アプリケーション側で独自の正規化ロジックを持たない
- `builder` が raw を直接解釈しない
- v1.1.0 フェーズ中に orchestration を先走って一般化しない

---

## 3. 正本の配置

identity 正本は以下に統一する。

```text
scripts/lib/identity/
  ├ primitive/
  ├ base_norm.py
  ├ field/
  └ builder/
```

`common.py` ベースの旧設計には戻さない。

---

## 5. v1.1.0 の現在の再開ポイント

最初の実戦投入対象は `hia_import_zip.py` とする。

再開時は以下の順で進める。

1. raw取得箇所を洗い出す
2. 旧正規化ロジックを特定する
3. スクリプト内の直接正規化を除去する
4. `identity.field` 呼び出しへ置換する
5. `identity.builder` で `person_id_custom` / `identity_hash` を生成する
6. 既存結果との差分を確認する

---

## 6. このフェーズでまだやらないこと

- event モデルの正式テーブル化
- orchestration の完成
- 便利ラッパーの一般化
- すべての既存スクリプトへの一斉展開

このフェーズでは、**ズレない構造を先に固定すること**を優先する。

v1.0.3 で共通キー整備は完了した。
