Draft.

## Pattern Classification

ヒロオカCSVは、CSV取込パターンAとして扱う。

- `header_mode = SINGLE`
- `header_structure_type = SIMPLE_HEADER`
- `header_context_rule = NONE`
- `active_header_row_no = 1`
- `data_start_row_no = 2`

特徴:

- 1行ヘッダーに基本情報、検査結果、判定、問診、予備列が横並びで並ぶ。
- 検査項目名と値種別はヘッダー名に含まれる。
- `値` / `判定` のような同名ヘッダー反復ではなく、`BMI 判定`, `腹囲 判定`, `空腹時血糖 判定` のように列名が具体化されている。
- 空腹時/随時は補助列で分岐するのではなく、`空腹時血糖` / `随時血糖`, `空腹時中性脂肪` / `随時中性脂肪` として別列で表現される。
- `【身体測定】総合判定` など、カテゴリ単位の総合判定列がある。
- `22予備` などの予備列が多い。

## Mapping Implications

ヒロオカCSVでは、結果値マッピングは `SINGLE_NAMECODE` + `DIRECT` を中心に組める。

例:

- `空腹時血糖` -> 空腹時血糖の `target_namecode`
- `随時血糖` -> 随時血糖の `target_namecode`
- `空腹時中性脂肪` -> 空腹時TGの `target_namecode`
- `随時中性脂肪` -> 随時TGの `target_namecode`
- `BMI 判定` や `腹囲 判定` は、同じrule内で `source_role = JUDGEMENT` として扱う

このCSVでは、補助列の値によって行ごとに保存先namecodeを分岐する必要は薄い。
ただし、`健診前の食事状況` は補足情報として保持し、将来の判定や確認材料にできる。

基本情報と検査結果値は、同じマッピングルール形式で抽出できる。

- 基本情報は `target_kind = LEDGER_FIELD` とし、`target_field` で `csv_row_ledger` の登録先を指定する。
- 検査結果値は `target_kind = EXAM_ITEM_VALUE` とし、`target_namecode` を固定指定する。
- 値列は `source_role = VALUE` とする。
- 判定列は同じ親rule内の `source_role = JUDGEMENT` とする。
- 本CSVには下限/上限列は見当たらないため、`LOWER_LIMIT` / `UPPER_LIMIT` のconditionは作らない。
- 完全空値のVALUEは `exam_item_values` 行を作らない。
- 判定だけが存在し、VALUEが完全空の場合も `exam_item_values` 行を作らない。

## Normalize / Value Handling Review

このCSVをエラーなく扱うため、normalizeと変換辞書で確認が必要な実値がある。

### Numeric Values

数値系の主な値は、通常の整数または小数である。

例:

- `身長`: `178`, `172.2`
- `BMI`: `23.7`, `27.8`
- `平均 収縮期`: `122`, `114`
- `HbA1c（NGSP)`: `5.2`, `5.3`

初期仕様の `PQ` / `INT` / `REAL` 数値normalizeで処理可能。

### Code-Like Values

尿定性、問診、判定、所見などは、数値ではなくCD/COまたはSTとして扱う必要がある。

代表値:

- 尿定性: `（－）`, `（±）`, `（＋）`
- 判定: `Ａ`, `Ｂ`, `Ｃ６`, `Ｃ１２`, `Ｄ`
- 所見: `異常所見なし`, `平低 T`, `完全左脚ブロック/洞徐脈`
- 問診: `いいえ`, `はい`, `喫煙`, `飲酒（月に1～3日）`, `飲まない（飲めない）`
- 特定健診判定系: `非該当`, `基準該当`, `予備群該当`, `情報提供`, `積極的支援`, `動機付け支援`

方針:

- `異常所見なし` は共通ノイズではなく、項目に応じた結果値として扱う。
- `いいえ` / `はい` も共通ノイズではなく、問診項目の結果値として扱う。
- 尿定性の `（－）` / `（±）` / `（＋）` はCD/CO辞書 `norm_variants` で扱う。
- 全角判定 `Ａ` / `Ｂ` / `Ｃ６` / `Ｃ１２` / `Ｄ` は健診機関由来の健診判定であり、初期実装ではPHR側判定や納品判定に使わない。
- `未実施` / `測定不能` / `判定不能` など、entry内の項目結果値として出てくる実施状態・測定可否は、上記の健診機関由来判定とは別に扱う。
- これらの値を `INVALID_VALUE_TYPE` にしないため、対象namecodeの `data_type` と辞書/変換ルールの組み合わせを確認する。

### norm_variants Coverage

既存の `sql/export_sql/norm_variants.sql` を確認した結果、ヒロオカCSVの実値には、既存辞書で解決できるものと追加が必要なものが混在している。

`norm_variants` は `result_code_oid + raw_value_utf8` の完全一致で引くため、同じ意味でもCSV上の表記が違えば未登録になる。
ヘッダー表記揺れと同じく、システム側で憶測吸収はしない。
取り込むと決めた実値は辞書へ追加し、あえて未登録にする実値は `NORMALIZE_VARIANT_NOT_FOUND` の検証対象として扱う。

4. 辞書追加後、同じCSVを再取込し、該当行が正常化されることを確認する。

### Missing Values

値なしの列は多いが、完全空VALUEは `exam_item_values` を作らないためエラーにはしない。

確認済み:

- `カナ氏名`: 全7行で空欄。
- `住所`: サンプルでは空欄。
- `随時血糖`: 列はあるがサンプルでは値なし。
- `随時中性脂肪`: 列はあるがサンプルでは値なし。
- `医師の指示事項`: 列はあるがサンプルでは値なし。

これらは取込停止理由ではない。
ただし、`カナ氏名` 空欄などは後続checkで健診機関確認項目として扱う。

## Rule Coverage Review

ヒロオカCSVを取り込むために、現行マッピングルール案で必要な表現は以下。

| requirement | current rule model |
| --- | --- |
| 1行ヘッダー830列のfingerprint | `csv_format_versions.header_mode = SINGLE`, `header_sha256`, `header_snapshot_json` |
| 基本情報列の抽出 | `target_kind = LEDGER_FIELD` |
| 結果値列の抽出 | `target_kind = EXAM_ITEM_VALUE`, `source_role = VALUE` |
| 判定列の付随登録 | 同一rule内の `source_role = JUDGEMENT` |
| 空腹時/随時の別namecode登録 | 列ごとに別 `target_namecode` を指定 |
| 空VALUEを登録しない | CSV取込処理方針で対応済み |
| CSV由来コード値の名寄せ | `phr_master.norm_variants` |
| 問診の文章値 | CD/CO辞書またはSTとして扱う |
| 欠落・確認項目の記録 | 後続check/確認項目として扱う |

この範囲では、パターンAのヒロオカCSVを表現するために、マッピングテーブル構造の追加は不要と判断する。
不足しうるのはテーブル構造ではなく、対象namecodeごとの具体的なマッピング定義、CD/CO辞書、transform ruleである。

## Check / Confirmation Items

初期取込では停止させず、後続checkまたは確認項目として扱う候補:

- `カナ氏名` が全件空欄。
- `住所` が空欄。
- `随時血糖` / `随時中性脂肪` が列として存在するが、サンプルでは値なし。
- `医師の指示事項` は列として存在するが、サンプルでは値なし。
- `報告区分` / `プログラム種別` に相当する明示列は見当たらない。`コース名称` から推定できる可能性はあるが、初期取込では自動推測しない。

## Initial Review Result

ヒロオカCSVは、CSV健診結果取込の初期実装に対する検証サンプルとして採用する。

- 初期実装ではパターンAの代表として扱う。
- header fingerprintは1行ヘッダー830列を列順込みで算出する。
- 登録済みヘッダー内で未マッピングの予備列・対象外列は、意図的な非取込列として扱う。
- このCSVを取り込めるかを検証するため、基本情報、Article44/特定健診に関わる主要検査、問診・判定系について、マッピング/ルール/normalizeの過不足を確認する。
- 実値で確認すべき主な論点は、尿定性記号、全角判定、問診文章値、所見文、空VALUE、`カナ氏名` 空欄である。
