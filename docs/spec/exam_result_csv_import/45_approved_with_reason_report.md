# 理由ありOK一覧・CSV出力

## 目的

XML出力済み、出力待ち、BLOCKEDなどcaseの現在状態に関係なく、人が理由を記入して許容したチェック項目を確認・報告できるようにする。

## 初期対象

`exam_case_check_review_items.review_status = 'APPROVED_WITH_REASON'` の現在有効な判断を対象とする。
caseの `case_status`、`export_readiness_status`、`xml_export_status`、lifecycleは抽出条件にせず、現在値として併記する。

再取込などで `RESOLVED_BY_SOURCE_VALUE` へ変わった過去の理由ありOKは、初期一覧へ混在させない。
過去判断は監査ログから復元可能なため、必要になった時点で「現在／履歴」の表示切替を追加する。

## 画面と出力

- HOMEのユーティリティに配置する。
- イベント、チェック種別、現在の出力可否状態に加え、記号、番号、氏名カナ、氏名、資格状態・資格喪失日、HIA加入者ID、subscriber ID、case IDで絞り込む。
- 健診機関は共通の健診機関選択モーダルから指定する。alias登録済みの健診機関を検索結果の上位に表示する。
- 絞り込みモーダルでは条件設定だけを行い、CSV出力は絞り込み後の候補一覧から実行する。
- 画面にはcase、対象者、健診機関、受診日、チェック項目、元のNG理由、人が入力した理由、判断日時・判断者、現在の出力状態を表示する。
- CSVは画面と同じ条件を使い、最大50,000項目をUTF-8 BOM付きで出力する。
- 1case（1人・1受診）を1行とし、基本情報、法定、特定健診を列で分ける。
- 法定・特定健診に複数の理由ありOKがある場合は、項目名・項目コード・理由を各セル内に改行して全件表示する。
- 同一加入者に複数の受診caseがある場合は、受診情報や出力状態を混在させないためcaseごとに別行とする。

既存テーブルの参照だけで実装し、新しいmigrationは追加しない。
