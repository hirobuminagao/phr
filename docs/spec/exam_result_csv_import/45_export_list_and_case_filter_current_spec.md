# 出力リスト・個人case絞り込み 現在仕様

## 1. 文書の位置づけ

2026-08-31時点で実装済みの、出力リスト詳細と個人case一覧の画面・検索挙動をまとめる。

XML生成条件やZIP構造は `34_csv_to_hia_xml_export_design_draft.md`、加入者1人に限定したcase再実行は `44_case_scoped_rebuild_screen.md` を正とする。本書はその上に載る運用画面の現在仕様であり、複数加入者のcase再実行仕様ではない。

## 2. 出力リスト詳細

### リスト名

- 詳細画面の変更ボタンからモーダルを開いて変更する。
- 常設の入力欄では直接編集しない。
- 更新は監査ログへ記録する。

### XML出力

出力先と梱包方式を別軸として扱う。

| 出力先 | 選択できる梱包方式 | 挙動 |
| --- | --- | --- |
| 確認 | 健診機関・受診月別 / リスト全員を単一DATA | 確認用ZIPを生成する |
| 本番 | 健診機関・受診月別のみ | 梱包方式を画面・サーバの両方で固定する |

単一DATAは確認用だけで利用する。送付元健診機関番号は必須で、画面初期値は `1322100106` とする。対象caseに複数の保険者番号が含まれる場合はエラーにしてZIPを生成しない。

本番へ切り替えた際もレイアウトが上下にずれないよう、注意文を含む操作領域の高さを安定させる。Windows版Chromeを含め、注意文はブラウザ固有の表示条件に依存させない。

## 3. 出力リストへの候補追加

既存の加入者・健診機関・受診月・出力可否条件に、健診項目条件を追加できる。

- 健診項目は専用モーダルで `exam_item_master` から複数選択する。
- 健診項目内の一致方法は `いずれか（OR）` / `すべて（AND）` を切り替える。
- 健診項目条件と既存条件の間は常にANDとする。
- 既に出力リストへ追加済みのcaseを重複追加しない。
- 候補検索だけでは出力リスト本体を変更せず、追加操作で保存する。

健診項目検索は共通の軽量検索処理を使う。日本語キーワードでASCII照合順序の `namecode` 列も検索できるよう、コード列はUTF-8へ変換して比較する。CSVマッピング画面と出力リスト画面で検索SQLの前提を分けない。

## 4. 個人case一覧の絞り込み

画面上部の絞り込み領域を2列に分ける。

| 左列 | 右列 |
| --- | --- |
| 従来の基本条件 | 健診項目条件 |

各列には現在の条件をバッジ表示し、それぞれの変更ボタンから専用モーダルを開く。モーダル内の `条件をセット` は検索を即実行せず、画面上の保留条件を更新する。

両方の条件を設定した後、共通の `この条件で絞り込む` ボタンで検索を実行する。条件式は次のとおりである。

```text
基本条件
AND
健診項目条件（選択項目のいずれか OR 選択項目のすべて）
```

健診項目未選択時は基本条件だけを適用する。基本条件未指定時は健診項目条件だけを適用する。両方未指定ならevent内の全caseを対象とする。

絞り込みは一覧行だけでなく、次にも同じ条件を適用する。

- case総数と状態別集計
- ページ送り
- 集計カードからの状態絞り込みURL
- 一覧CSVダウンロード

条件変更後、共通の実行ボタンを押す前は `条件変更あり` と表示し、現在表示中の結果と未適用条件を区別する。

## 5. APIエラー表示

モーダル内検索など画面遷移を伴わないAPIで未処理例外が発生した場合も、HTMLの内部エラー画面へ遷移させずJSONで次を返す。

- エラーメッセージ
- ログID
- 管理者向けエラー詳細URL

画面側はログID、コピーボタン、詳細リンクを表示する。CSVマッピングの項目検索と出力リストの健診項目検索は、この共通エラー表示を使用する。

## 6. 実装境界と未実装

- 健診項目条件はcaseの採用済み値を検索対象とし、raw CSV列を直接検索しない。
- 出力リスト候補と個人case一覧は同じOR/ANDの意味を使う。
- 個人case一覧の絞り込みはcaseを更新せず、表示対象を変えるだけである。
- 複数加入者を選んだcase再実行は未実装である。
- 今回の画面・検索同期にDB migrationやseedは不要である。
