# 外部指摘ワークフロー再設計

## 目的

外部指摘を「箱」「対象者」「指摘項目」の3階層で管理し、修正・確認・再出力までを一続きに追跡する。
再出力後に同じ対象者へ別の指摘が届いた場合は、過去の箱を再利用せず新しい箱から開始する。

## 管理単位

```text
指摘箱 report
  対象者 item（複数、原則case単位）
    指摘項目 detail（複数）
      BASIC_INFO / EXAM_ITEM / OTHER
```

- 基本情報と健診項目を同じ対象者へ同時に登録できる。
- 対象者の状態は指摘項目から集約する。
- 箱の状態は対象者から集約する。
- 原本値やcase値の修正処理は既存画面で行い、この機能は指摘と対応履歴を記帳する。

## 状態と不変条件

- 指摘項目がすべて `RESOLVED` の対象者だけを解決済みとする。
- 解決済みでも、caseの `export_readiness_status` が出力可能でなければ出力リストへ追加しない。
- 出力リストは箱と同じeventのものだけ選択できる。
- 出力リスト追加後も指摘箱と対象者は削除しない。追加先リストcase IDを保持する。
- `CARRIED_OVER` の箱は参照専用とし、対象者追加、明細追加、状態変更を禁止する。

## 未解決の引き継ぎ

「未解決を引き継ぐ」は1トランザクションで次を行う。

1. 元箱をロックし、引き継ぎ済みでないことを確認する。
2. 新しい箱を作り、`copied_from_report_id` に元箱IDを記録する。
3. `RESOLVED` 以外の指摘項目だけを、新しい対象者・指摘項目として複写する。
4. 元箱を `CARRIED_OVER` にし、`carried_over_to_report_id` に新箱IDを記録する。
5. 元箱を参照専用にする。

解決済み項目は新箱へ複写しない。対象者に指摘項目がない場合は未解決として対象者だけを引き継ぐ。

## 画面

1. 外部指摘一覧: 箱を作成し、箱ごとの人数・未解決数・引き継ぎ元/先を確認する。
2. 指摘箱詳細: 1人ずつの検索と対象者リスト貼り付けの両方から対象者を複数追加し、解決済み対象者を選んで出力リストへ追加し、未解決を新箱へ引き継ぐ。一括追加で特定できない行は削除せず、入力行とエラー理由を結果に残す。
3. 対象者詳細: 基本情報・健診項目・その他の指摘を複数追加し、項目ごとに状態と対応メモを更新する。

## DB差分

- report: `copied_from_report_id`, `carried_over_to_report_id`
- item: `copied_from_item_id`, `reoutput_xml_export_list_case_id`
- detail: `copied_from_detail_id`, `resolved_at`, `resolved_by`

既存テーブルを拡張し、新しい管理テーブルは増やさない。
