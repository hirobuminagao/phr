# 外部指摘ワークフロー設計レビュー

## 結論

設計は実装可能。既存の3階層を維持し、系譜と再出力先だけを追加するため、機能の肥大化を抑えられる。

## レビューで修正した点

- `WONT_FIX` と `CANCELLED` は解決済み再出力の条件に含めない。再出力可は全項目 `RESOLVED` の場合だけとする。
- 対象者の手動状態と明細状態がずれないよう、明細更新時に対象者・箱の状態を再集約する。
- 元箱の画面を隠すだけでなく、更新APIでも `CARRIED_OVER` を拒否する。
- 出力可否は指摘機能だけで決めず、既存caseのreadinessを必ず再確認する。
- 出力リストへの二重追加は既存の一意制約と再追加処理を利用する。

## 残余リスク

- 過去データの対象者状態は明細状態と一致しない場合がある。画面操作後は再集約されるが、一括backfillは今回行わない。
- `WONT_FIX` を業務上再出力可にする必要が出た場合は、理由必須と承認権限を別途設計する。
- 箱単位で出力リストを新規作成する機能は含めず、既存リストへの追加に限定する。
