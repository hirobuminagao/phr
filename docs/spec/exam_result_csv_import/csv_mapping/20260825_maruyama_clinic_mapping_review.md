## 形式判定

既存のヒロオカ/厚木/渋谷Westhills Pattern Aとは一致しない。

- 既存Pattern Aは830列。
- 円山CSVは1075列。
- 先頭列が `社員番号, 保険証記号, 保険証番号, 受診日（西暦）...` で、既存Pattern Aの `受診日付, 受診者コード, 受付番号...` とは並びも列名も異なる。

そのため、既存Pattern Aのclone seedではなく、円山専用のCSV format versionとヘッダー名指定のmapping ruleを追加する。

## 初版mapping方針

初版は、CSV取込とcase作成・法定/特定チェックに必要な基本情報および主要な健診項目を優先して登録する。

- 基本情報は `exam_ledgers` の既存LEDGER_FIELDに入る範囲だけをmappingする。
- 受診券整理番号、有効期限はCSV列として存在するが、CSV取込時点で直接入れるledger fieldが未整備のため、初版seedではmappingしない。
- 健診機関側問い合わせ用の `facility_document_id` に該当しそうな列は今回サンプルでは明確に確認できないため、初版seedではmappingしない。
- 判定列は施設独自判定として扱い、標準CDやSTへ機械的に安全に変換できるもの以外は初版mappingしない。
- 特記事項系は、まずテキストそのものをSTとして取り込める項目を優先する。所見有無CDへの派生は別途確認して追加する。

## 注意点

- `中性脂肪` と `血糖` は空腹/随時の識別列が見えていない。初版seedでは既存チェックが進むことを優先して空腹側へmappingするが、円山側の仕様確認が必要。
- `クレアチニン` は主要列に直接見つからず、`NTx（尿）クレアチニン` のみ確認できたため初版mapping対象外。
- 医師名に該当する列は確認できていない。特定健診で必要になる場合は、医療機関へ列提供可否を確認する。
- 受診券整理番号・有効期限は列あり。CSV取込からcase export fieldへ反映する設計を別途整備すればmapping対象にできる。
