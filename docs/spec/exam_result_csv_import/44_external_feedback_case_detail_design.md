# 外部指摘のcase・指摘項目管理設計

## 目的

外部から一度に返却された指摘を受領単位で管理しながら、対象caseごと、さらに指摘項目ごとに対応状況を記帳する。
同一caseに住所、医師名、検査結果コードなど複数の指摘がある場合も、個別に未対応・解決済みを判断できるようにする。

## 管理階層

```text
ops_external_feedback_reports          受領単位（メール、ZIP、エラー一覧）
  ops_external_feedback_items          対象単位（原則case。ZIP全体指摘はcaseなしも許容）
    ops_external_feedback_item_details 指摘項目（基本情報、健診項目、その他）
```

`ops_external_feedback_items` は既存名を維持するが、業務上はcase明細として扱う。

## 指摘項目の種類

| 種類 | 必須識別情報 | 例 |
| --- | --- | --- |
| `BASIC_INFO` | `basic_field_code` | 氏名、生年月日、保険者番号、住所、受診日、健診機関 |
| `EXAM_ITEM` | `namecode`。必要に応じて `section_code` | 検査値、単位、結果コード、所見、医師名 |
| `OTHER` | 指摘内容 | XML構造、ZIP、ファイル名、アップロード、再提出 |

指摘項目は外部エラーコード、指摘内容、指摘値、期待値、修正後値、対応メモ、状態を持つ。

## 状態

指摘項目は `OPEN / CONFIRMED / FIX_PLANNED / WAITING_RESUBMISSION / RESUBMITTED / RESOLVED / WONT_FIX / CANCELLED` を使用する。
case明細と受領単位の状態は当面明示更新を維持し、自動集約は状態変更画面を整備する段階で追加する。
下位項目が残っているのに上位を解決済みにする場合は、将来警告を表示する。

## 既存データ移行

既存のcase明細が持つ `issue_category`、`namecode`、`check_item_code`、エラー内容、値、対応メモを、指摘項目1件へ複写する。
既存列は一覧互換と段階移行のため削除しない。新規登録時も最初の指摘項目を同時作成する。

## 初期画面

1. 外部指摘一覧からcase明細の詳細を開く。
2. case、対象者、健診機関、受領元を確認する。
3. 指摘項目一覧で種類・識別子・内容・状態を確認する。
4. 種類を選び、同じcaseへ指摘項目を何件でも追加する。
5. case詳細への導線から、実データの確認・修正へ進む。

初期実装では追加と参照を対象とし、項目編集・状態の自動集約・一括登録は次段階とする。
