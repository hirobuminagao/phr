# CSVマッピング条件分岐エディタ設計メモ

2026-09-02 UI方針合意、初期実装完了。本書を初期実装の仕様とする。

## 1. 目的

CSVヘッダーの値によって、同じ取り込み先へ異なる固定値を登録する条件分岐ルールを、CSVマッピングテンプレート編集画面から作成・編集できるようにする。

条件分岐の対象は、結果OIDを持つ `CD` / `CO` の健診項目に限定する。取り込み先の健診項目を選ぶまでは条件分岐を選択できず、固定登録値は選択項目の標準コード候補から選ぶ。自由入力はさせない。

初期対象は次のようなルールである。

- 胸部X線判定が `A` の場合、所見の有無へCD `2`（異常所見なし）を登録する。
- 胸部X線判定が空欄ではなく `A` 以外の場合、CD `1`（異常所見あり）を登録する。
- 空欄は初期設定では出力しない。

聴力判定のraw値 `正常` / `低下` は条件分岐ではなく既存normalizeの同義語追加として扱う。

- `正常` -> CD `2`（異常所見なし）。
- `低下` -> CD `1`（異常所見あり）。

## 2. 現状

健診項目追加・編集モーダルは次を画面設定できる。

- `1:1`。
- `1:n 結合`。
- `条件分岐`。

`1:1`と`1:n 結合`は `value_source_type = SOURCE`、`fixed_value = NULL`、`SOURCE_COLUMN`条件として保存する。`条件分岐`は同一グループの複数ruleとして比較条件と固定出力値を保存する。画面で作成した条件分岐グループは、一まとまりとして再編集・削除できる。

DBと共通抽出処理には、条件付き固定値に必要な次の表現がすでに存在する。

- `value_source_type = FIXED`。
- `fixed_value`。
- `EQUALS`、`NOT_EQUALS`、`NOT_EMPTY`等のoperator。
- 同一targetへの複数rule。
- 同一condition group内のAND。

このため、現時点では新規migrationを前提としない。画面、保存API、再編集用payload、複数ruleのグループ管理を主な実装対象とする。

## 3. 決定した操作フロー

1. 既存の健診項目追加・編集モーダルを開く。
2. 既存どおり取り込み先項目を選ぶ。
3. 既存どおり判定に使用するCSVヘッダーを選ぶ。
4. 方式から `条件分岐` を選ぶ。
5. `条件を追加` または `条件を設定` を押し、条件設定用の別モーダルを開く。
6. 条件設定モーダルで空欄時の処理と分岐条件を設定する。
7. `条件を決定` で元のマッピングモーダルへ戻る。
8. 元のモーダルに条件分岐の要約カードを表示する。
9. `マッピングに追加` または `変更を保存` で条件一式を保存する。

取り込み先とCSVヘッダーを条件設定モーダルで再選択させない。元のモーダルで選択した値を条件設定モーダルへ引き継ぐ。

- 取り込み先未選択時は `条件分岐` を無効にする。
- 選択項目が `CD` / `CO` 以外、結果OIDなし、標準コード候補なしの場合も無効にする。
- 登録値は選択項目の結果OIDに紐づくcanonicalな `norm_variants.normalized_code` と表示名を候補にする。

## 4. 条件設定モーダル

### 4.1 空欄時の処理

条件一覧とは分離し、モーダル最上部へ共通設定として固定する。

```text
空欄時の処理
[出力しない] [出力する]
```

- 初期値は `出力しない`。
- `出力する` を選んだ場合だけ、空欄時の登録値を入力する。
- 空欄判定は個別条件より先に評価する。
- 空欄を出力しない場合、後続の `A以外` 条件へ空欄を含めない。

### 4.2 条件分岐

空欄時の処理の下へ、条件カードを追加できる領域を置く。

```text
条件1
判定: 一致する
比較値: A
登録値: 2: 異常所見なし（選択）
表示名: 異常所見なし

条件2
判定: 一致しない
比較値: A
登録値: 1: 異常所見あり（選択）
表示名: 異常所見あり

[条件を追加]
```

初期実装で選択可能にする判定候補は次とする。

- 一致する。
- 一致しない。
- いずれかに一致する。
- 空欄・空欄ではないは上部の空欄設定と内部の `NOT_EMPTY` 条件で扱い、初期画面の個別条件には出さない。

初期実装では、条件カード1件につき比較条件は1件とする。`いずれかに一致する`はカンマ区切りで複数値を指定する。複数の条件カードは、互いに重複しない条件として設定する。

どの条件にも一致しない場合は出力しない。将来、未該当時の処理を追加する場合も、空欄時の処理とは別設定にする。

## 5. 元モーダルへ戻った後の表示

条件設定の詳細を元モーダルへ展開しすぎず、次の要約を表示する。

```text
条件分岐 2件
空欄: 出力しない

A -> 2 異常所見なし
A以外 -> 1 異常所見あり

[条件を変更]
```

取り込み先、判定CSVヘッダー、条件件数、空欄方針、各出力値を保存前に一画面で確認できることを必須とする。

## 6. 保存表現

条件カード1件を、同一targetへ向く条件付き固定値rule 1件として保存する。

保存APIでも対象項目が `CD` / `CO` であること、固定登録値がその結果OIDのcanonicalな候補に含まれることを検証する。画面payloadを書き換えて候補外の値を保存することはできない。

胸部X線の例は次の2ルールになる。

1. `胸部X線判定 EQUALS A` -> `FIXED 2`。
2. `胸部X線判定 NOT_EQUALS A` -> `FIXED 1`。

`NOT_EQUALS` ruleには空欄方針にかかわらず `NOT_EMPTY` をAND条件として保存する。空欄を出力する設定では、`EMPTY`条件を持つ固定値ruleを同じグループへ追加する。

同一モーダルで作成した複数ruleは、既存 `selection_group_code` を使って再編集時に一まとまりとして復元する。rule keyの文字列解析には依存しない。

## 7. 実データチェックとの接続

保存後はCSVマッピング実データチェック画面で次を確認できるようにする。

- 取り込み先と判定CSVヘッダー。
- raw値ごとの件数。
- 変換後CDごとの件数・割合。
- 空欄件数と空欄時の処理。
- 成立した条件カード。
- どの条件にも一致しなかった件数。
- 複数ruleが同時成立した競合件数。

今回の胸部X線例では、`A -> CD 2`、`B/C/D2等 -> CD 1`、空欄は出力なしとなることを実CSVで確認する。

## 8. 初期実装範囲

1. 条件設定モーダルと元モーダル間の状態管理。
2. 条件付き `FIXED` ruleの作成・更新・グループ削除。
3. `selection_group_code`による分岐グループの復元。
4. 空欄を出力しない `NOT_EQUALS` ruleへの `NOT_EMPTY` 自動付与。
5. 通常importと実データチェックで共通の条件評価を使用。
6. normalizeへの聴力判定 `正常` / `低下` 追加。
7. 条件評価の単体テスト。
