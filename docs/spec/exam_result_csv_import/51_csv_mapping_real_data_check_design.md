# CSVマッピング実データチェック設計

2026-09-02 初期実装済み。実装正は `scripts/lib/csv/mapping_data_check.py` と `apps/health_exam_admin` のdata-check画面/APIを参照する。

## 1. 目的

CSVマッピングテンプレートへ設定したルールを実CSVへ仮適用し、本取込前に変換結果の妥当性を確認する。

小禄の聴力で発生した、raw値と変換後CDの意味が逆になる問題のように、処理自体は成功していても結果分布が不自然な設定を発見できることを主目的とする。

本機能はdry-runであり、通常取込、file receipt、ledger、case、検証履歴を作成・更新しない。

## 2. 利用条件と導線

- CSVマッピングテンプレート詳細に「実データでチェック」を配置する。
- 表示中の保存済みテンプレートと、保存済みかつ有効なルールを使用する。
- テンプレート自体が無効でも実行できる。無効から有効へ変更する前の確認を主要用途とする。
- 未保存の画面編集内容と無効ルールは対象外とする。
- 利用権限はCSVマッピング編集権限 `can_manage_business_settings` に集約し、専用権限は追加しない。
- 権限のないユーザーには導線を表示せず、URL/APIへの直接アクセスも403にする。

## 3. 画面フロー

1. テンプレート詳細から実データチェック画面を開く。
2. 対象テンプレート名、健診機関、状態、データ開始行、ヘッダー構造、対象ルール数を確認する。
3. CSVをドラッグ＆ドロップまたはファイル選択する。
4. サーバーで文字コードとヘッダーを解析し、保存済み基準ヘッダーと比較する。
5. 一致時はそのままチェックを開始できる。
6. 不一致時は、追加、欠落、列順のみの差、context差を表示する。ユーザーが差分を確認して明示的に続行した場合だけチェックを開始する。
7. 項目別集計と行単位プレビューを表示する。
8. 別CSVを選ぶか、テンプレート詳細へ戻る。

ヘッダー確認と実行は分離したAPIにする。ブラウザーが選択中の同じFileを保持し、差分確認後に再送することで、確認待ちのCSVをサーバーやDBへ保管しない。

## 4. 入力条件

- 対応文字コードはUTF-8 BOM、UTF-8、CP932を初期対象とし、既存 `CSVLoader` の自動判定を使う。
- delimiter、quote char、ヘッダー行、実ヘッダー行、データ開始行は保存済みテンプレート設定を使う。
- 対象データは先頭最大10,000行とする。ただし10,000行をメモリへ保持せず、一時ファイルから1行ずつ逐次処理する。
- 空行は通常importと同じ条件で処理対象外とし、空行件数を別表示する。
- 10,000行を超えるファイルは全行数を数えるが、10,000行を超えた実値を保持・変換しない。マッピング対象外の列も行処理後に保持しない。
- アップロード容量には上限を設ける。初期値は既存アップロード制限に合わせ、未設定なら50MBとする。

画面には、CSV全データ行数、処理対象行数、空行数、上限超過により未処理となった行数を明示する。割合の分母は空行を除く実際の処理対象行数とする。

## 5. ヘッダー差分判定

保存済み `header_snapshot_json` とアップロードCSVの正規化済みヘッダーを比較する。比較には列番だけを使わず、次を使う。

- header name。
- context。
- occurrence。
- column numberは列順差の説明に使用する。

差分区分:

- `MATCHED`: 完全一致。
- `ORDER_ONLY`: 同じ項目が存在し、列順だけが異なる。
- `ADDED`: アップロード側だけに存在する。
- `MISSING`: 基準側だけに存在する。
- `CONTEXT_CHANGED`: header nameは一致し、contextが異なる。
- `AMBIGUOUS`: 同名・同contextの重複により一意に解決できない。

`MATCHED`以外がある場合は警告する。ただし、保存済みルールの全参照列を一意に解決できる場合は、確認後に続行できる。参照列が欠落または曖昧な場合も実行自体は許可し、該当ルールをヘッダー不足として結果へ出す。

## 6. 処理構成

### 6.1 共通化方針

通常importとdry-runで別の変換ロジックを作らない。

1. `load_csv_mapping_rules(..., csv_result=...)` で有効ルールと解決済み列を取得する。
2. `extract_row_values()` で条件評価、固定値、1:1、1:n結合を適用する。
3. `EXAM_ITEM_VALUE` は `get_exam_item()` と `normalize_exam_item_value()` でCD/CO/PQ/STを変換・検証する。
4. dry-run用集計へ結果を渡す。
5. 通常importだけが同じ結果を `exam_item_values` へINSERTする。

CSVの全行・全列や全変換結果をリスト化しない。現在処理中の1行、target別集計カウンター、画面表示上限内のサンプルだけをメモリへ保持する。項目マスタと、対象namecode/result code OIDに必要なnorm variantは実行中にキャッシュし、行・項目ごとの同一DB参照を避ける。

現状の `insert_exam_item_value()` はnormalizeとINSERTを同時に行うため、実装時に次へ分離する。

- DBへ書き込まず `NormalizedExamValue` と対象項目情報を返す共通評価関数。
- 評価済み結果をINSERTする通常import専用関数。

これにより画面プレビューと実取込結果の差を防ぐ。

### 6.2 テンプレート読込

既存 `get_csv_format_version_by_id()` は `is_active = 1` を条件に持つため、そのままでは無効テンプレートを検証できない。ID指定で無効テンプレートも取得できるlookupを追加し、画面・dry-runはそれを使う。ルールは従来どおり有効ルールだけを読み込む。

### 6.3 行処理

各行について次を保持する。

- CSV行番号。
- rule ID、rule key、target kind、target namecodeまたはtarget field。
- 参照した列番号とraw値。
- 結合前raw値、結合後raw値。
- matched condition group。
- 変換後のnormalized valueまたはcode value/display。
- normalize status/reason。
- validation status/reason。
- dry-runエラー区分。

全10,000行分の実値表示データは保持しない。集計は全処理対象行で行い、画面表示用には各項目の先頭100件とエラー行最大1,000件だけを保持する。超過したエラー行数は省略件数として表示する。

## 7. 集計仕様

### 7.1 共通ヘッダー

項目ごとに次を表示する。

- 取込先項目名、namecodeまたはledger field。
- データ型。
- 適用ルール、参照CSVヘッダー、条件概要。
- 処理対象行数。
- 値あり件数・率。
- 空欄件数・率。
- 変換成功件数・率。
- 変換失敗件数・率。
- 条件不一致件数・率。
- 複数ルール競合件数・率。

分母は実際に処理した行数とする。15,000行のCSVを10,000行まで処理した場合、すべての割合の分母は10,000行と表示する。

### 7.2 CD・CO

- 変換後code value、display name、件数、全処理対象行に対する割合を表示する。
- 各変換後コードの配下に、そのコードとなったraw値別の件数と割合を表示する。
- `CO`はコード単位の集計と、1行内のコード組み合わせ単位の集計を表示する。
- 空欄、変換辞書なし、validation失敗をコード集計と並ぶ独立区分として表示する。

表示例:

```text
聴力（右・1000Hz） CD
処理 10,000 / 値あり 9,850 (98.5%) / 空欄 150 (1.5%)
CD 2 異常所見なし 9,500 (95.0%)
  raw 1: 9,500
CD 1 異常所見あり 350 (3.5%)
  raw 2: 350
変換失敗 0 (0.0%)
```

### 7.3 PQ

- 値あり、空欄、成功、失敗の件数・率を表示する。
- normalized value、unit、raw valueを行単位でプレビューする。
- 初期実装では最小、最大、平均等の統計値は必須としない。

### 7.4 ST・基本情報

- `ST`の詳細分布集計は初期実装では省略してよい。
- 設定済みであること、値あり・空欄・失敗の件数は共通ヘッダーへ表示する。
- `LEDGER_FIELD`も同様に値あり率とraw値を確認できるようにするが、氏名等を含むため画面を開ける権限はCSVマッピング編集権限に限定する。

### 7.5 1:n・条件付き固定値

- 1:n結合は参照元ヘッダーと各raw値、除外値、separator、最終結合値を表示する。
- 条件付き固定値は成立したcondition group、条件概要、固定値を表示する。
- どの条件にも一致しない行と複数ルールが同一targetへ値を生成した行を独立して集計する。

## 8. エラー区分

- `HEADER_MISSING`: 参照ヘッダーがない。
- `HEADER_AMBIGUOUS`: 参照ヘッダーを一意に解決できない。
- `NO_CONDITION_MATCH`: 条件groupに一致しない。
- `RULE_CONFIGURATION_ERROR`: 固定値や結合設定が不足している。
- `MULTIPLE_RULE_MATCH`: 同一targetへ複数ルールが値を生成した。
- `INVALID_VALUE_TYPE`: 値型が不正。
- `NORMALIZE_FAILED`: norm variantなし等で変換できない。
- `VALIDATION_FAILED`: normalize後のvalidationが不正。

内部reasonは保持するが、画面には日本語ラベルと内部reasonを併記する。

## 9. API・画面構成案

- `GET /admin/csv-mapping-templates/{id}/data-check`
  - チェック画面を表示する。
- `POST /api/admin/csv-mapping-templates/{id}/data-check/header`
  - CSVの文字コード、行設定、ヘッダー差分だけを返す。
- `POST /api/admin/csv-mapping-templates/{id}/data-check/run`
  - 同じCSVを再送し、最大10,000行のdry-run集計を返す。
  - ヘッダー差分がある場合は `header_mismatch_confirmed=true` を必須とする。

レスポンスは、ファイル概要、ヘッダー差分、全体件数、target別集計、target別プレビューで構成する。巨大なJSONを避けるため、実値プレビューは上限を設ける。

## 10. データ破棄とセキュリティ

- multipart uploadは一時ファイルとして扱い、成功、業務エラー、例外のすべてで `finally` により削除する。
- DB、監査用テーブル、セッション、アプリログへCSV本文、raw値、氏名等を保存・出力しない。
- 検証履歴と集計結果は保存しない。
- エラーログにはtemplate ID、ファイルサイズ、文字コード、処理件数、内部エラーコードだけを残す。
- CSRF、アップロード容量、拡張子、MIME、CSV parseエラーを既存管理画面と同じ入口で検証する。
- ブラウザー上の結果は画面遷移・再読込で破棄する。

## 11. DB変更

新しい永続テーブル、migration、seedは不要とする。

変換には既存の次を参照する。

- `phr_master.csv_format_versions`。
- `phr_master.csv_exam_result_mapping_rules`。
- `phr_master.csv_exam_result_mapping_conditions`。
- `dev_phr.exam_item_master`。
- `phr_master.norm_variants`。

## 12. テスト方針

### 単体テスト

- 無効テンプレートをID指定で読み込める。
- 無効ルールは対象外になる。
- ヘッダー完全一致、列順差、追加、欠落、context差、重複を分類できる。
- 10,001行以上でも保持・変換は10,000行で止まり、総行数と未処理件数を返す。
- 1:1、1:n、条件付き固定値が通常importと同じ結果になる。
- CD/COのraw別・code別割合が処理対象行数を分母にする。
- PQ、空欄、normalize失敗、validation失敗を正しく集計する。
- 同一targetの複数ルール一致を検出する。
- 一時ファイルが成功時と例外時の両方で削除される。

### 結合・画面テスト

- CSVマッピング編集権限あり・なしで画面/APIが制御される。
- ヘッダー差分未確認ではrunできず、確認後はrunできる。
- 10,000行、複数target、1,000件超エラーでも画面が崩れない。
- Windows Chromeでアップロード、警告、集計、横スクロールを操作できる。
- 小禄の聴力サンプルでraw値とCDの件数・割合が確認できる。

## 13. 設計レビュー

### 採用してよい点

- 有効化前の無効テンプレートを実データで確認する目的と導線が一致している。
- 通常importと同じextract/normalize処理を使うため、プレビュー専用実装による判定差を抑えられる。
- 実データを永続化せず、既存のCSVマッピング編集権限へ集約する境界も現在のヘッダープレビューと整合する。
- CD/COをraw値と変換後コードの両方向から集計するため、変換が成功しているだけでは発見できない意味の逆転を見つけやすい。

### 実装前に必ず対処する点

1. 現在のCSV loaderは全行をメモリへ保持する。10,000行制限だけ画面側へ追加してもメモリ保護にならないため、一時ファイルから1行ずつ読み、処理済み行を保持しないストリーミングreaderを追加する。既存loaderの挙動変更で通常importへ影響させず、共通parser設定だけを再利用する。
2. 現在のnormalizeはINSERT関数内で呼ばれる。dry-run独自実装を作らず、評価と保存を分離して通常importの回帰テストを追加する。
3. `get_csv_format_version_by_id()` は無効テンプレートを返さない。既存関数の意味を変えず、無効を含めて取得する別lookupを追加する。
4. 「先頭100件＋全エラー」を無制限にDOMへ出すと、全件エラー時に画面が破綻する。集計は全件、表示はエラー最大1,000件とし、省略数を表示する。
5. ヘッダー差分確認のためにサーバーへファイルを保持しない。ブラウザーが同じFileを再送する二段階APIとする。
6. 通常importの条件不一致は必ずしもエラーではない。条件付き固定値等では正常な非該当があるため、必須ルール、selection mode、同一target内の他ルール成立状況を加味して警告レベルを決める。

### レビュー結論

上記6点を実装条件に含めれば、既存DB構造を変更せず実装可能である。特に、評価処理の共通化と条件不一致の扱いを先にテストで固定してから画面を作ることを推奨する。
