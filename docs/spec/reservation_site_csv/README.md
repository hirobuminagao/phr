# 予約サイトCSV取込

## 目的

イベントごとに共有される予約サイトCSVを `work_other` に取り込み、予約サイト側の最新状態と変更履歴を保持する。PHR加入者・健診結果との紐付けや利用方法は後続仕様とし、第一段階ではアップロード、検証、INSERT/UPDATEを成立させる。

## 識別と更新

- CSV 3列目の `id` を予約システム全体で一意な予約IDとする。
- `reservation_site_records.reservation_id` にUNIQUE制約を設定する。
- 同じ予約IDを別eventへ付け替えない。event不一致はエラーにする。
- CSVの `updated_at` がDBより古い場合は上書きしない。
- HIA加入者IDは重複しうるため識別キーにせず、検索用indexだけを設定する。
- CSVに存在しない予約を自動削除・無効化しない。

## テーブル

- `reservation_site_records`: 予約ごとの最新状態
- `reservation_site_record_options`: 横持ち8枠の追加オプションを位置付きで保持
- `reservation_site_record_history`: 予約・オプションの列差分履歴
- `reservation_site_facility_mappings`: 予約サイト医療機関IDとPHR健診機関マスタIDの全event共通対応
- `etl_runs` / `etl_errors`: 取込実行記録

施設対応が未登録でも予約は取り込む。後から施設名を見て手作業で対応を登録できる設計とする。

## 追加オプション

CSVには `OP HIAコード`、`OP 名称`、`OP 価格` が最大8組、同名ヘッダーで横並びになる。列名辞書ではなく物理列位置で読み取る。ヘッダーの組数および各データ行の列数は可変で、実際に存在するオプション分の3列だけ出力される場合がある。固定35列は厳密に照合し、後続は0〜8組の3列セットとして読み、存在しない枠を空欄として補完する。3列に満たない半端な組や、ヘッダーの組数を超えるデータは列ずれとしてエラーにする。

- 今回も同じ枠に値がある: 更新
- 新しい枠に値がある: 追加または再有効化
- 予約行はあるが前回の枠が空になった: `is_active=0`
- 予約ID自体がCSVにない: オプション状態を変更しない

## 画面フロー

1. HOMEのユーティリティから予約サイトCSV取込を開く。
2. eventを選択し、CSVをドラッグ＆ドロップする。
3. 事前確認で追加・更新・変更なし・エラー・未対応施設を確認する。
4. エラーがなければ確認済み計画を反映する。
5. 反映時はCSVを再解析せず、事前確認時の計画を使用する。

## 項目方針

- 原文が必要な外部コード・氏名・保険情報はraw相当列を保持する。
- 保険者番号、氏名カナ、保険証記号番号はPHR共通正規化による照合列を別途保持する。
- `applicant_sex`、`terminal_type`、`canceller` は意味を推測せず原値保存する。
- `tel_timezone` はNULL可。0から23なら電話希望時間帯の時として補助列にも保持する。
- 予約状態はCSV原文を保持する。画面では判明済みの `1=仮予約`、`3=予約済み`、`4=受診済み`、`5=キャンセル` を表示し、それ以外は原値表示とする。
