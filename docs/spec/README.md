

# docs/spec 運用ルール

## 目的

`docs/spec` は、本プロジェクトで採用する仕様書を管理するディレクトリとする。

設計検討中の内容は `docs/refactor`、制度原本は `docs/mhlw` に配置し、仕様として採用した内容のみを `docs/spec` に配置する。

---

## ディレクトリの役割

| ディレクトリ | 役割 |
|--------------|------|
| docs/mhlw | 厚生労働省等の原本資料 |
| docs/refactor | リファクタリング・設計検討・設計履歴 |
| docs/spec | 採用済み仕様書 |

---

## バージョンルール

### 現行仕様

現行システム・現行運用を整理した資料は、現行バージョンをファイル名に付与する。

例

```text
01_medi_xml_result_handling_v1.0.0.md
```

### v2仕様

v2で採用する仕様書は、仕様上のバージョン表記を `v2.0.0` で統一する。

ファイル名では `.` を使用せず、`_` を使用する。

例

```text
02_exam_check_item_spec_v2_0_0.md
03_exam_item_master_v2_0_0.md
04_exam_check_result_spec_v2_0_0.md
```

- 仕様書本文では `v2.0.0` のように通常のバージョン表記を使用する。
- ファイル名では `v2_0_0` のように `.` を `_` に置き換えて命名する。

---

## 更新ルール

- 軽微な追記・修正ではファイル名のバージョンは変更しない。
- 設計内容の更新は、設計履歴 (`docs/refactor/health_exam_result/05_design_history.md`) に記録する。
- システム全体の仕様変更や大規模な設計変更が発生した場合のみ、次メジャーバージョン（例: 仕様表記 `v3.0.0`、ファイル名 `v3_0_0`）を検討する。

---

## 基本方針

- 原本は `docs/mhlw` を正とする。
- `docs/spec` は原本をプロジェクト仕様へ翻訳・整理した資料とする。
- 実装・DDL・スクリプトは `docs/spec` を参照して作成する。
- リファクタリング中の検討事項は `docs/refactor` に残し、採用後に `docs/spec` へ反映する。
