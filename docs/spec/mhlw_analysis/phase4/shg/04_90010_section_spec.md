# 90010 指導共通情報 セクション仕様

## ■ 目的

本ファイルは、厚生労働省「特定保健指導XML仕様（5-1A）」を親資料とし、その中の 90010 セクション（指導共通情報セクション）について整理するものである。

付属3に記載された 90010 セクションの構造と、付属3を正規化した `fuzoku3.csv` の項目情報を対応づけ、健診・保健指導機関等 → 医療保険者の XML 仕様として section 単位で参照しやすい形に固定することを目的とする。

※ 本ファイルは実装方針の定義ではなく、仕様上の事実整理を目的とする。

※ 本ファイルで主対象とするのは、`5-1A` が定義する「健診・保健指導機関等 → 医療保険者」向け XML 仕様である。法定報告項目の列は参照するが、保険者 → 国の報告 XML 仕様そのものを本ファイルで定義するものではない。

## ■ 前提（項目FIXベース）

90010 セクションで扱う項目は、`fuzoku3.csv` において項目単位で FIX 済みとする。
本ファイルでは、その FIX 結果を section 単位で整理し、90010 に属する項目群を明示する。

---

## ■ セクション概要

90010 は、指導共通情報セクションである。

5-1A および付属3では、以下の7項目を対象とするセクションとして整理されている。

- 保健指導区分（項目コード `1020000001`）
- 行動変容ステージ（項目コード `1020000002`）
- 保健指導コース名（項目コード `1020000003`）
- 健診実施年月日（確認用）（項目コード `1020000004`）
- 保健指導後服薬1（項目コード `1020000005`）
- 保健指導後服薬2（項目コード `1020000006`）
- 保健指導後服薬3（項目コード `1020000007`）


また、本セクションは以下を含む。

- 人が解釈するための説明ブロック（`text`）
- 機械可読表現である 1 個の `entry` 要素（内部に複数 observation を保持しうる）

## ■ 説明ブロック仕様（表17・表18ベース）

本節は、5-1A 3.3.2.2（表17・表18）を一次根拠として整理する。

### 1. text 要素

`text` 要素は必須である。

説明ブロックには `list` と `item` を用いた表示用テキストを記述する。

### 2. 表示対象として明示されている項目

表17では、少なくとも以下の表示用テキストが定義されている。

| 項目 | 値（表示用テキスト） |
|------|----------------------|
| 保健指導区分 | `積極的支援` / `動機付け支援` / `動機付け支援相当` |
| 行動変容ステージ | `意志なし` / `意志あり（６か月以内）` / `意志あり（近いうち）` / `取組済み（６ヶ月未満）` / `取組済み（６ヶ月以上）` |
| 保健指導コース名 | コース名文字列 |

### 3. XML構造（表18ベース）

| XPath | 内容 | 多重度 | 選択性 | 備考 |
|------|------|--------|--------|------|
| `/ClinicalDocument/component/structuredBody/component/section/text` | 説明ブロック | `1..1` | `M` | |
| `list` | 項目リスト | `0..1` | `O` | |
| `list/item` | 項目 | `1..*` | `M` | list が存在する場合 |
| `list/item/text()` | `項目名 値（表示用テキスト）` | `1..1` | `M` | 項目名と値の間は半角スペース |

### 4. 補足

仕様書では、保健指導後服薬1〜3 や健診実施年月日（確認用）について、text 側では必須表示対象としては並んでいない。
また、これらについては任意であり、まったく記述しなくてもよいが、その場合でも `text` 要素自体は必須とされている。

## ■ エントリ部仕様（3.3.2.3 / 表19ベース）

5-1A 3.3.2.3（表19）に基づき、90010 セクションの entry 配下について、確認できた事実を以下に整理する。

- `entry` は `1..1 M`
- `entry` の中に、各項目コードに対応する `observation` が入る
- サンプルでは `act classCode="ACT" moodCode="EVN"` 配下に `entryRelationship typeCode="COMP"` を繰り返す形で表現されている
- 各 observation の `code/@code` に項目コードを設定する
- 値は項目に応じて `value xsi:type="CD"` または `value xsi:type="ST"` となる
- 健診実施年月日（確認用）（`1020000004`）は、サンプル上 `ST` かつ `YYYYMMDD` 形式で表現されている
- XPath は section 構造の事実参照用として保持する

## ■ このファイルで固定する事実

- 90010 は「指導共通情報セクション」である
- 90010 では 1101〜1107 を section 対象項目として扱う
- 現在のプロジェクトスコープでは、1101〜1104 を主対象として整理する
- 1105〜1107 は `fuzoku3.csv` の法定報告列に現れる参考項目として保持する
- `text` は必須である
- `entry` は 1..1（内部に複数 observation を含む）
- `code/@code` は `90010`
- `code/@codeSystem` は `1.2.392.200119.6.1010`
- 説明ブロックは `list/item` 形式で記述できる
- サンプル上、保健指導区分・行動変容ステージは `CD`、コース名と健診実施年月日（確認用）は `ST` で表現される
- 表19で確認できた entry 配下の主要XPath（11.7〜11.13.7）は、section 構造の事実参照用として本ファイル内に保持する

---

## ■ 現時点の整理方針

- 表19では、entryRelationship ブロックを計 1〜4 項目分だけ繰り返す旨が記載されている
- 1..4 は `5-1A` における insurer-facing XML の構造事実として扱う
- 1105〜1107 は `fuzoku3.csv` の法定報告列に現れるが、現在スコープでは保険者 → 国の報告 XML 仕様そのものは定義対象外とする
- よって本ファイルでは、1105〜1107 を section 対象項目として保持しつつ、現行実装の主対象は 1101〜1104 とする

## ■ 事実確認時の更新ポイント

後日、PDF・付属3・XMLサンプル・matrix整理などにより事実を再確認した場合は、以下の観点で更新箇所を切り分ける。

- **親資料・参照箇所の誤り**
  - 更新箇所：`## ■ 親資料と参照資料` / `### ■ 主な参照箇所（5-1A）`
  - 例：章番号、表番号、親資料名、付属資料の位置付け

- **項目コード・項目名・値型・出現条件の誤り**
  - 更新箇所：`## ■ 項目対応（付属3 / fuzoku3 ベース）`
  - 例：1101〜1107 の項目コード、CD/ST、first_claim / legal_report 条件

- **section / text / entry 構造事実の誤り**
  - 更新箇所：`## ■ セクション部仕様（表16ベース）` / `## ■ 説明ブロック仕様（表17・表18ベース）` / `## ■ エントリ部仕様（3.3.2.3 / 表19ベース）`
  - 例：entry の持ち方、entryRelationship の繰り返し数、observation 構造、XPath 参照

- **本ファイル内の説明用整理の見直し**
  - 更新箇所：`## ■ セクション概要` / `## ■ サンプルから読み取れる項目対応` / `## ■ このファイルで固定する事実`
  - 例：7項目の説明順、entry の説明粒度、サンプル由来の補足表現

- **未確定事項が確定した場合**
  - 更新箇所：`## ■ 留保事項`
  - 例：1105〜1107 を insurer-facing XML 側でも扱うべきか、国報告側仕様と分けて保持すべきか、matrix 側との対応

※ 実装やスクリプト修正時に仕様確認が入った場合、まずこの section spec と `fuzoku3.csv` と `report_timing_and_section_matrix.md` のどれが事実ソースかを切り分け、憶測ではなく一次情報確認後に更新すること。
