

# ADR 0005: exam_item_master における「付属2（健診項目一覧）」由来フラグの保持方針（phase4 / v08）

## ステータス
- 提案 → 採用（v1.0 freeze 後の前提固定。実装反映は v1.1 以降で可）

## 背景
PHR v1.0 では、CDA（健診）出力の構造として「法令等で定められた項目群」と「任意追加項目群」をセクション分割して格納する前提がある。
- 仕様（PDF）: `docs/mhlw/phase4_v08/3-1A.pdf`
- 付属2（健診項目一覧）: `docs/mhlw/phase4_v08/001082795.xlsx`（シート: `付属2(健診項目一覧)`）

一方、現状の `exam_item_master`（付属2由来 seed を含む）には、付属2の **A列/ B列** に相当する「実施要件」および「法定報告」フラグが未保持、または保持方法が未確定である可能性がある。
この情報は、今後の
- CDA 出力（01010 / 01990 のセクション分割）
- 「法定（必須）」判定や欠損チェック（LSIO 等）
- 将来の制度期（第5期等）への拡張
における一次前提となるため、**DBカラム設計に先立って前提を文書で固定**する。

## 目的
- 付属2（健診項目一覧）を一次情報として、exam_item_master に保持すべきフラグ・概念を定義する
- CDA 出力側のセクション分割（01010 / 01990）を **推測ではなく根拠ベース**で行えるようにする
- 例外（後期高齢者で任意化する項目等）を、後から拡張可能な形で表現する

## 仕様上の要点（一次情報の解釈）
### 1) 付属2（健診項目一覧）の列の意味
シート `付属2(健診項目一覧)` には、少なくとも以下の判定軸が存在する。

- **A列: 実施項目**
  - 記号（○/□/●/☆）で「実施要件」を示す
  - 注記（例）:
    - ○…必須項目
    - □…医師の判断に基づき選択的に実施する項目
    - ●…いずれかの項目の実施で可
    - ☆…入手できた場合に報告

- **B列: 法定報告項目**
  - 「法定報告」の対象であるかどうかを示す（空欄/非空欄）
  - 本プロジェクトでは **CDAのセクション分割（01010 / 01990）の一次判定に利用**する

### 2) 注釈による例外
付属2の注釈には「後期高齢者では任意となる項目」が明示されている（腹囲・喫煙等）。
従って、単純な「B列のみ」判定では制度対象によって例外が生じうる。

ただし v1.0 freeze フェーズでは、まず **B列による一次判定を固定**し、例外適用は v1.1 以降の拡張として扱う。

## 決定（方針）
### A) exam_item_master に保持する概念（カラム候補）
`exam_item_master` は、namecode/identity_item_code 等の識別子に加え、付属2由来の以下の概念を保持できるようにする。

- `annex2_exec_requirement`（A列の実施要件）
  - 値例: `MUST` / `OPTIONAL_BY_DOCTOR` / `EITHER_OK` / `REPORT_IF_AVAILABLE`

- `annex2_legal_report_flag`（B列の法定報告フラグ）
  - 値例: `1/0`（または enum）

- `cda_section_code_default`（出力セクションのデフォルト）
  - 値例: `01010` または `01990`
  - ルール（一次）:
    - `annex2_legal_report_flag = 1` → `01010`
    - `annex2_legal_report_flag = 0` → `01990`

> 注: 上記カラムは v1.0 の freeze を壊すため「即時必須」ではない。
> v1.1 以降のDDL固定化フェーズで追加・seed化し、当面は「未使用」を明文化して保持する。

### B) 例外（後期高齢者など）は別テーブルで表現する
例外は、将来増える可能性があり、カラムで抱えると破綻しやすい。
従って **別テーブル**で override を表現する。

- テーブル案: `exam_item_section_overrides`
  - `identity_item_code` / `namecode`
  - `applies_to`（例: `KOKI`=後期高齢者）
  - `override_section_code`（例: `01990`）
  - `source_ref`（付属2の注釈※番号、ページ、ファイル名）

### C) export 側の当面の運用（v1.0）
- v1.0 では、現状の `exam_item_master` が `annex2_legal_report_flag` 等を未保持である可能性があるため、
  **セクション分割の厳密実装は後回し**とする。
- v1.1 以降で、付属2列の取り込み（seed化）を実施し、`medi_export_xml.py` の section 生成ロジックで
  `01010` / `01990` を根拠ベースで分割できるようにする。

## 影響範囲
- DDL（`dev_phr.exam_item_master`）: カラム追加候補（未使用の明文化を含む）
- seed/固定データ: 付属2（xlsx）からの取り込み方針
- CDA出力（`scripts/kenshin_list_pydir/scripts/medi_export_xml.py`）: section分割ロジックの将来対応
- 法定欠損チェック（LSIO等）: 将来 `annex2_legal_report_flag` と組み合わせて精度向上

## 補足
- 付属2ファイルは数字名のため視認性が低い。将来、内容を変えずにファイル名の別名（alias）を付与する場合は、
  `README.md` に対応関係を記載し、元ファイルも併存させる（履歴と根拠保持のため）。
