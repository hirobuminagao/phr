

# ADR-0017: Event-centric data model gap and introduction of person-centric event model

## Status
Proposed

## Context

現行システムでは以下の構造でデータが管理されている：

- 健診予約システム（健診の実施・結果の一次受領）
- 特定保健指導システム（指導の実施・結果作成）
- HIA（加入者管理・結果集約・健保への納品）

これらのシステムはそれぞれ役割を持つが、データは以下の問題を抱えている：

- 実施イベント（受診・指導）は人に紐づいている
- 健診結果・保健指導結果はファイル単位またはシステム単位で管理されている
- 健診の請求情報は人単位で統合されていない
- 健診結果は複数経路（健診予約システム / 健保・事業所）から流入する

その結果：

**同一人物に紐づく一連のイベント（実施・結果・請求）が統合されておらず、イベント単位での一貫した管理ができていない。**

---

## Problem

現行モデルでは、

- 「人」
- 「実施」
- 「結果」
- 「請求」

がそれぞれ独立して管理されており、

**“同一イベント”として束ねる構造が存在しない**

---

## Decision

以下の方針を採用する：

### 1. 人中心モデルの採用

すべてのデータは人を中心に管理する。

### 2. イベントの分離と統合

イベントは以下のように分離する：

- 実施イベント
- 結果
- 請求

ただし、これらは同一イベントとして束ねて管理する。

### 3. イベント枠の導入

イベントは制度に基づく「イベント枠」として定義し、

- 健保
- 年度
- 健診種別

を単位として管理する。

### 4. イベント単位での統合

同一人物・同一イベントに属する

- 実施
- 結果
- 請求

を統合して扱う構造を導入する。

---

## Consequences

### Positive

- 人単位でのイベント管理が可能になる
- 健診・特定保健指導の統合的な管理が可能になる
- 複数経路からのデータ流入を統合できる
- 未受診・重複・補助判定などの制御が容易になる

### Negative / Trade-offs

- 既存システムとの整合調整が必要
- イベント識別（event_id）の設計が必要
- データ統合ロジックの複雑性が増す

---

## Notes

本ADRは「イベント単位で管理できていない現状の問題」を明確化し、  
人中心イベントモデル導入の方向性を示すものである。

具体的なイベント識別子（event_id）や実装設計は別ドキュメントで定義する。
