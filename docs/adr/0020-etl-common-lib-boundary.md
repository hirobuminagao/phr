# ADR-0020: ETL共通ライブラリの責務境界

## ステータス
採用（Accepted）

---

## 背景（Context）

PHRシステムでは、ETL処理を標準化するために共通ライブラリ（`scripts/lib/etl`）を導入する。

このライブラリは以下を共通化することを目的とする：

- ETL実行管理（`etl_runs`）
- 行単位エラーログ（`etl_errors`）
- メトリクス収集（処理件数など）

しかし、責務の境界が曖昧な場合、以下のリスクがある：

- 業務ロジックが共通ライブラリに混入する
- 責務が不明確になる
- 再利用性・保守性が低下する

また現在、ETL管理テーブルは以下のように**スキーマ並行運用**されている：

- `dev_phr`
- `work_other`

この構成により、ETL実行管理の扱いが曖昧になる可能性がある。

---

## 決定（Decision）

### 1. ETL共通ライブラリの役割

ETL共通ライブラリは**基盤レイヤ（foundation layer）に限定する**。

実施すべきこと（MUST）：

- ETL実行ライフサイクルの管理（`start_run`, `finish_run`）
- 実行結果の記録（`etl_runs`）
- 行単位エラーの記録（`etl_errors`）
- メトリクスコンテナの提供（`RunMetrics`）
- 進捗ログ出力機能の提供

実施してはならないこと（MUST NOT）：

- 業務ロジックの実装
- データ正規化処理
- マッピング解釈
- ドメイン固有バリデーション
- identity照合処理

---

### 2. 責務分離

| コンポーネント | 責務 |
|----------------|------|
| metrics        | 事実の保持（件数のみ） |
| runs           | ライフサイクル管理・ステータス判定 |
| errors         | エラー記録 |
| ddl            | テーブル存在保証 |
| progress       | ログ出力のみ |

ETLスクリプト（呼び出し側）の責務：

- データ処理
- メトリクス更新
- エラー発生のトリガ
- トランザクション制御（`commit / rollback`）

---

### 3. スキーマ運用方針

ETL管理テーブルは現在、以下のスキーマで並行運用されている：

- `dev_phr.etl_runs` / `dev_phr.etl_errors`
- `work_other.etl_runs` / `work_other.etl_errors`

ルール：

- `run_id` はスキーマ内でのみ一意
- `run_id` はグローバル一意ではない
- ETLスクリプトは対象データと同一スキーマのETLテーブルを使用する

例：

- `dev_phr.staging_subscribers_fund`
  → `dev_phr.etl_runs` を使用

今後の検討事項（未決定）：

- スキーマ統合
- ETL専用スキーマの導入

---

## 影響（Consequences）

### 良い点

- 基盤と業務ロジックの明確な分離
- ETL共通ライブラリの高い再利用性
- 保守性・拡張性の向上
- ETL実行管理の一貫性確保

### 注意点

- ETLスクリプト側での実装規律が必要
- スキーマ並行運用により一部重複が発生する可能性

---

## 移行メモ（Transitional Note: v1.0.3 → v1.1.0）

本基盤導入時点では、以下の状態が存在する：

- 一部業務機能（例: `subscribers_fund`）は v1.0.3 の設計・課題を起源とする
- ただし実装は v1.1.0 の共通ETL基盤（`scripts/lib/etl`）上で行う

整理：

- 業務テーマ：v1.0.3 の継続
- 実装アーキテクチャ：v1.1.0

本フェーズは、
**「旧業務課題を新基盤へ移行・再構築する段階」**
と定義する。
