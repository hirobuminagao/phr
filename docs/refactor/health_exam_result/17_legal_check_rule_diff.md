# 旧法定健診チェックルールと v2 制度チェック仕様の差分

## 概要

既存の `LSIO_Legal_Item` ルールは、XML内に法定健診項目が存在するかを同一性項目コード単位で確認するための最小限のpresenceルールである。一方、`02_exam_check_item_spec_v2_0_0.md` は、法定健診・特定健診の制度チェック結果を `exam_check_results` の `status_<同一性項目コード>` / `reason_<同一性項目コード>` に落とすための仕様であり、算出、代替、条件付き必須、理由情報まで扱う前提になっている。

結論として、既存 `LSIO_Legal_Item` は v2 の法定健診チェックにそのまま流用するには不足がある。単純な項目存在判定の土台としては使えるが、v2 migration で同一性項目の追加・整理を行い、スクリプト側で算出・代替・条件付き判定・status/reason生成を補う必要がある。

## 比較対象

- 旧ルール: `dev_phr.exam_item_group_identity_members` の `group_code = 'LSIO_Legal_Item'`
- 補助マスタ: `exam_item_group_members`、`exam_item_group_method_members`、`exam_item_master`
- v2仕様: `docs/spec/health_examinations/02_exam_check_item_spec_v2_0_0.md`
- 比較軸: v2仕様のうち、法定健診側として `労働安全衛生法` 欄が `○` または `△` の同一性項目

注意: v2仕様には `法定報告項目` 欄もあるが、今回は特定健診側の警告・報告中心チェックは扱わず、`LSIO_Legal_Item` と比較するために労働安全衛生法側に限定している。`法定報告項目` 欄を主判定に含めるべきかは要確認。

## 既存 `LSIO_Legal_Item` の登録状況

`exam_item_group_identity_members` に登録されている同一性項目は29件である。

| required_flag | 同一性項目コード |
| --- | --- |
| `1` | `1A010`, `1A020`, `2A020`, `2A030`, `3B035`, `3B045`, `3B090`, `3D010`, `3F015`, `3F050`, `3F070`, `3F077`, `9A110`, `9A750`, `9A760`, `9D100`, `9E160`, `9N001`, `9N006`, `9N016`, `9N051`, `9N056`, `9N061`, `9N066`, `9N206` |
| `0` | `2A040`, `6A010`, `6A205`, `7A010` |

`required_presence_namecodes` が設定されているのは `9N206` のみである。`9N206160700000011` と `9N221160700000011` のどちらかが存在すれば、胸部X線ありとみなす。

`presence_value_mode` が設定されているのも `9N206` のみで、値は `ANY_NONEMPTY` である。ただし旧STEP 1の実装上は、`medi_xml_item_values` に対象 `namecode` 行があるかどうかを見ており、値が非空か、nullFlavorか、コード値が妥当かまでは判定していない。

## 差分一覧

### 既存のみ

| 同一性項目コード | 既存required_flag | 判断 |
| --- | ---: | --- |
| `3F050` 総コレステロール | 1 | v2仕様の法定健診対象にはなく、代わりに `3F069` non-HDL がある。non-HDL算出に使う補助値として扱うのか、旧ルールから外すのか要確認。 |
| `7A010` 喀痰細胞診 | 0 | v2仕様の法定健診対象にはない。旧ルール上も任意扱いなので、v2主判定からは外す方向でよさそうだが要確認。 |

補足: `exam_item_group_members` には `9N511` 医師の診断、`9N512` 検査未実施理由なども含まれるが、`exam_item_group_identity_members` には登録されていない。旧presence判定の対象ではないため、今回の「既存のみ」には含めない。

### required_flag差分

v2仕様の `労働安全衛生法` 欄が `○` の項目は、旧 `required_flag = 1` とおおむね一致している。

| 同一性項目コード | v2仕様 | 既存required_flag | 判断 |
| --- | --- | ---: | --- |
| `9N006`, `9N051`, `9N056`, `9N061`, `9N066`, `9A750`, `9A760`, `1A010`, `1A020`, `9E160` | `○` | 1 | 主判定必須として流用できそう。 |

v2仕様の `労働安全衛生法` 欄が `△` の項目は、旧マスタでは `required_flag = 1` と `0` が混在している。これは旧マスタが「再提出・確認フローの主判定」として強めに必須扱いしている可能性があり、単純に誤りとは断定できない。

| 同一性項目コード | v2仕様 | 既存required_flag | 判断 |
| --- | --- | ---: | --- |
| `9N001`, `9N016`, `3B035`, `3B045`, `3B090`, `3F015`, `3F070`, `3F077`, `3D010`, `2A020`, `2A030`, `9A110`, `9D100`, `9N206` | `△` | 1 | 旧ルールでは必須。v2では条件付き・省略基準・代替可能性を `status/reason` で表す必要がある。 |
| `2A040`, `6A010`, `6A205` | `△` | 0 | 旧ルールでは任意。v2でも主判定で必須にするか、条件付き/確認対象にするか要確認。 |
| `9N011`, `9N021`, `3F069`, `3D046`, `2A021`, `9N211`, `9N221`, `9N226` | `△` | 未登録 | migration追加と、required相当の扱いを要確認。 |

既存 `3F050` は `required_flag = 1` だが、v2仕様の法定健診対象にはない。既存 `7A010` は `required_flag = 0` だが、v2仕様の法定健診対象にはない。

### presenceルール要確認

| 項目 | 要確認内容 |
| --- | --- |
| `9N206` / `9N221` / `9N211` / `9N226` 胸部X線 | 旧ルールは `9N206` 1項目に直接・間接の「所見の有無」をOR集約している。v2仕様は胸部X線系を複数の同一性項目コードとして持つため、`status_9N206` だけでよいのか、`status_9N221` 等も生成するのか要確認。 |
| `3D010` / `3D046` 血糖・HbA1c | 旧ルールは血糖 `3D010` のみ。v2仕様ではHbA1c `3D046` も代替・併記可能な項目として扱うため、ORまたは代替判定が必要。 |
| `3F069` / `3F050` / `3F070` non-HDL | 旧ルールは総コレステロール `3F050` を必須にしているが、v2仕様はnon-HDL `3F069` を持つ。算出元として総コレステロールを使うのか、non-HDL実値を必須視するのか要確認。 |
| `9N011` BMI | 旧ルールにはない。身長・体重から算出できるため、実値がなくても `status_9N011 = 算出` のように扱う可能性がある。 |
| `9N016` / `9N021` 腹囲・内臓脂肪面積 | 旧ルールは腹囲のみ必須。v2仕様では内臓脂肪面積が代替・条件付き候補に見えるため、代替判定が必要。 |
| `2A020` / `2A030` / `2A040` / `2A021` 貧血系 | 旧ルールは赤血球数・血色素量を必須、ヘマトクリット値は任意、貧血検査 `2A021` は未登録。v2仕様では医師判断・実施理由を含む可能性があり、主判定条件は要確認。 |
| `9A110` 心電図 | 旧ルールは必須。v2仕様では医師判断・要実施理由系の注記があるため、実施理由や対象者コードを reason に反映するか要確認。 |
| `9D100` 聴力 | 旧ルールは必須。v2仕様では `△` で、省略・方式差があり得るため、左右・周波数の揃い方をどう判定するか要確認。 |

## v2でそのまま流用できそうな項目

presence検出の入口としては、以下は `exam_item_master.identity_item_code` とのJOINで判定できそうである。

- `9N006`, `9N051`, `9N056`, `9N061`, `9N066`
- `9A750`, `9A760`
- `1A010`, `1A020`
- `3B035`, `3B045`, `3B090`
- `3F015`, `3F070`, `3F077`
- `2A020`, `2A030`, `2A040`
- `9E160`
- `6A010`, `6A205`

ただし、これは「対象 `namecode` があるか」を検出できるという意味であり、v2の `status_XXXX` / `reason_XXXX` を確定できるという意味ではない。値の空・nullFlavor・コード値・左右や周波数の揃い方・省略理由は別途判定が必要である。

## v2でmigration修正が必要な項目

| 対応 | 対象 |
| --- | --- |
| `exam_item_group_identity_members` に追加 | `9N011`, `9N021`, `3F069`, `3D046`, `2A021`, `9N211`, `9N221`, `9N226` |
| 既存必須の見直し | `3F050` を主判定必須に残すか、`3F069` の算出元・補助項目へ下げるか要確認。 |
| 既存任意の見直し | `2A040`, `6A010`, `6A205` を条件付き項目として残すか、主判定外にするか要確認。 |
| 主判定外候補 | `7A010` はv2仕様の法定健診対象にないため、`LSIO_Legal_Item` に残す必要があるか要確認。 |
| `required_presence_namecodes` 追加候補 | 胸部X線、血糖/HbA1c、腹囲/内臓脂肪面積、non-HDL算出、貧血系など。ただしOR集合だけで足りるかは要確認。 |
| `presence_value_mode` 拡張候補 | `ANY_NONEMPTY` だけでは算出・代替・条件付き・左右セット・非空値・nullFlavor除外を表せない。 |

## v2でスクリプト側判断が必要な項目

| 判断カテゴリ | 対象 | 必要な処理 |
| --- | --- | --- |
| 算出 | `9N011`, `3F069` | 身長・体重、総コレステロール・HDLから算出し、`status` に算出扱いを入れる。 |
| 代替 | `3D010` / `3D046`, `9N016` / `9N021`, `3F077` / `3F069` | どちらかがあれば充足とするのか、両方のstatusをどう表すのかを決める。 |
| 条件付き必須 | `2A020`, `2A021`, `2A030`, `2A040`, `9A110`, `9D100`, `9N206` 系 | 省略基準、医師判断、実施理由、対象者コードを reason に反映する。 |
| 複合項目 | `9D100`, `9E160`, `9A750`, `9A760` | 左右、周波数、複数回測定など、同一性項目コード内の複数 `namecode` の扱いを決める。 |
| 値妥当性 | 全項目 | presenceだけでなく、値が空でないか、nullFlavorをどう扱うか、コード値・単位が妥当かを判定する。 |
| reason生成 | 全項目 | `reason_<code>` に入れる不足理由、代替理由、算出理由、条件付き理由のコード体系を定義する。 |

## 結論

既存 `LSIO_Legal_Item` は、v2法定健診チェックのベースマスタとして一部流用できる。ただし、現状は旧presence判定用のルールであり、v2仕様の法定健診対象35件に対して項目集合が不足している。

特に、BMI、内臓脂肪面積、non-HDL、HbA1c、貧血検査、胸部X線の派生項目は旧identityルールに存在しない。また、総コレステロールと喀痰細胞診は旧ルールにだけ存在する。`required_flag` も、v2仕様の `○` / `△` と単純には対応していない。

したがって、v2 migrationでは `LSIO_Legal_Item` を棚卸しして、同一性項目コード単位の登録をv2仕様に合わせる必要がある。さらに、主判定である法定健診チェックでは、単なる項目存在ではなく、`status_<code>` / `reason_<code>` へ落とせる判定ロジックをスクリプト側に実装する必要がある。

## 次にやること

- v2仕様で法定健診主判定に含める同一性項目を、`労働安全衛生法` 欄ベースで確定する。
- `法定報告項目` 欄を法定健診主判定に含めるか、別の報告チェックとして扱うか決める。
- `LSIO_Legal_Item` のv2 migration方針を作る。追加候補は `9N011`, `9N021`, `3F069`, `3D046`, `2A021`, `9N211`, `9N221`, `9N226`。
- `3F050` と `3F069` の関係を決める。総コレステロールを必須のまま残すか、non-HDL算出元にするか要確認。
- 胸部X線を1つの主判定項目に集約するか、specどおり複数 `status_XXXX` を作るか決める。
- `ANY_NONEMPTY` の正式定義を決める。少なくとも非空値、nullFlavor、コード値妥当性を扱うか要確認。
- `status_<code>` / `reason_<code>` のコード体系を、算出・代替・不足・不正・条件付き省略に対応できる形で定義する。
